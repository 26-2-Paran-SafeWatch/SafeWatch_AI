# 데스크탑 데이터 세팅 요청 (강섬희)

**요청** 설만수 (AI 파트) · **작성** 2026-10-10
**목적** 모델 파인튜닝을 바로 돌릴 수 있도록 데스크탑(RTX 4070 / 2TB)에 AI Hub 데이터를 미리 받아두기

환경 설치 절차 전체는 [`docs/gpu-desktop-setup.md`](gpu-desktop-setup.md)에 있다. 이 문서는 **"무엇을 받아야 하는지"** 와 **"안 받아지는 함정"** 만 추린 것이다.

---

## 0. 시작 전에 이것부터 확인 — 막히면 나머지가 다 무의미

### AI Hub 승인은 **계정별**이다

내(설만수) 계정이 승인받은 것이지 데스크탑이 승인받은 게 아니다. 다운로드하려면 **그 계정의 API Key**가 필요하다. 셋 중 하나를 골라야 한다.

| 방법 | 필요한 것 | 내일 가능? |
|---|---|---|
| **A. 섬희 본인 계정으로 신청** | AI Hub 가입 → 데이터셋 4종 이용 신청 → 승인 대기 | ❌ **승인에 시간이 걸려 내일은 어려움** |
| **B. 내 계정 API Key로 받기** | 내가 키를 따로 전달 | ⭕ 가능 |
| **C. 내가 원격으로 접속해서 받기** | 데스크탑 원격 접속 수단 | ⭕ 가능 |

**→ 내일 돌리는 게 목표면 B나 C다.** A는 지금 신청해두면 나중에 편하니 **B/C로 진행하면서 A도 같이 신청**해두는 걸 권한다.

> B로 간다면 키는 메신저 본문에 적지 말고 따로 주고받자. 받은 키는 터미널에 직접 치지 말고 파일로 저장한다 (`gpu-desktop-setup.md` 5절). 예전에 키가 로그에 남은 적이 있어서 그 방식으로 정착했다.

## 1. 지금 우리한테 뭐가 없는 상태인가

맥에서 다운로드를 다섯 번쯤 시도했는데 **이미지는 한 장도 못 받았다.** 지금 가진 건 라벨뿐이다.

| | 상태 |
|---|---|
| 라벨 (도로주행영상 Validation) | ✅ 64MB, 받아서 YOLO 포맷 변환까지 검증 완료 (11,588개) |
| **이미지 (원천데이터)** | ❌ **0장.** 14GB짜리를 반복 시도했으나 매번 깨짐 — 원인은 아래 3절 함정 |

**즉 라벨만 있고 짝이 될 이미지가 없어서 학습을 못 돌린다.** 이번에 받아야 할 1순위가 이 이미지다.

## 2. 받을 데이터 — 우선순위 순

AI Hub 사이트에서 `dataSetSn` 번호로 찾으면 된다.

| 순위 | 데이터셋 | dataSetSn | 전체 용량 | 우리가 쓰는 이유 |
|---|---|---|---|---|
| **1** | 도로주행영상 | **180** | 277.89GB | **차량 검출 파인튜닝.** 지금 모델이 사전학습 그대로라 정확도가 낮다 — 이게 들어와야 S5가 시작됨 |
| 2 | 도로 로드마크 인식을 위한 주행 영상 | 654 | 1,005.77GB | 차선 인식 검증·튜닝 |
| 3 | 자동차 차종/연식/번호판 인식용 영상 | 172 | 231.15GB | 번호판 블러(개인정보 비식별화) |
| — | 교통사고 영상 데이터 | 597 | 3.79TB | **보류. 받지 말 것** — 용량 대비 우선순위 낮음 |

### ⚠️ 2TB에 1~3번을 다 받으면 안 들어간다

1~3번 합계가 **약 1.5TB**인데, 압축 해제할 때 원본 zip과 풀린 파일이 동시에 존재해서 **파일 크기의 3배쯤 여유 공간이 순간적으로 필요하다**(3절 참고). 다 받으면 압축을 못 푼다.

**이번엔 1번(도로주행영상, 278GB)만 받아줘.** 그것도 전부가 아니라 아래 순서로:

1. **Validation 원천데이터** ← 제일 급함. 지금 라벨만 있고 이미지가 없는 바로 그것
2. Validation 라벨링데이터
3. 여유 되면 Training 원천데이터 + 라벨링데이터

> 데이터셋이 `원천/라벨` × `부위(bb·fs·pg·sl)` × `도로유형`으로 수십 개 zip으로 쪼개져 있다. **우리가 쓰는 건 `bb`(bounding box)** 다 — 파인튜닝이 사각형 박스 기준이라서. `pg`(폴리곤)는 변환 작업이 따로 필요해서 지금은 안 쓴다.

## 3. 받는 방법 — 공식 도구 쓰지 말 것

### ❗ AI Hub 공식 `aihubshell`을 그대로 쓰면 안 된다

공식 스크립트에 **버그가 2개** 있다. 내가 맥에서 다운로드를 다섯 번 실패하고 나서야 찾아낸 건데, OS 문제가 아니라 스크립트 자체 결함이라 **데스크탑에서도 똑같이 재현된다.**

1. **다운로드가 끊겨도 "성공"이라고 보고한다** — 중간에 잘린 파일을 그대로 완성본 취급해서 넘어간다. 그래서 다 받은 줄 알았다가 압축 풀 때야 깨진 걸 알게 됨
2. **조각 파일 병합 순서가 뒤섞인다** — 대용량 파일은 1GB씩 조각나서 오는데, 정렬이 잘못돼서 순서가 섞인 채 합쳐진다. 14GB 파일(조각 14개)에서 **매번** 깨졌다

**고친 버전이 저장소에 있다 → `scripts/aihubshell_fixed.sh`**

```bash
cd ~/SafeWatch_AI          # 저장소 클론 후 (gpu-desktop-setup.md 3절)
git checkout dev
chmod +x scripts/aihubshell_fixed.sh
```

### 받는 순서

```bash
mkdir -p data/raw/aihub && cd data/raw/aihub
SHELL_PATH=../../../scripts/aihubshell_fixed.sh

# 1) 파일 목록부터 확인 — filekey 번호를 여기서 확인한다
$SHELL_PATH -mode l -datasetkey 180

# 2) 목록에서 Validation 원천데이터 / 라벨링데이터의 filekey를 찾아 지정
$SHELL_PATH -aihubapikey "$(cat ~/.aihub_api_key)" -mode d -datasetkey 180 -filekey <번호,번호>
```

> `-filekey`를 생략하면 **278GB 전체**가 받아진다. 처음엔 꼭 목록(`-mode l`)을 먼저 보고 필요한 것만 지정해줘. 목록 결과를 나한테 보내주면 어떤 번호를 받아야 하는지 짚어줄게.

## 4. 받고 나서 반드시 할 것

### ① 압축 풀기 전에 무결성 확인 (이거 건너뛰면 또 당함)

```bash
python3 -c "import zipfile; print('손상 있음' if zipfile.ZipFile('원천데이터.zip').testzip() else '정상')"
```

맥에서 **5번 중 3번이 깨져 있었는데** 압축을 푼 뒤에야 알았다. 깨졌으면 그 파일만 다시 받으면 된다.

### ② 한글 파일명 깨짐 대비

zip 안 한글 파일명이 CP949로 돼 있어서 리눅스 `unzip`이 깨뜨린다.

```bash
unzip -O cp949 원천데이터.zip -d extracted
```

`-O` 옵션이 없다는 에러가 나면 `gpu-desktop-setup.md` 7절의 Python 스크립트를 쓰면 된다.

### ③ 디스크 여유 확인

압축 해제 중엔 **파일 크기의 3배**가 필요하다. 맥에서 43GB 여유로 14GB 파일을 못 풀었다. 받기 전에 `df -h`로 확인해줘.

## 참고 — 같이 부탁하고 싶은 것 (데이터와 별개, 급하지 않음)

[`docs/hw-handoff-guide.md`](hw-handoff-guide.md) 3장으로 2주 전에 보낸 건인데 아직 회신을 못 받았다. 데이터 세팅하는 김에 같이 봐주면 좋겠다.

1. **카메라 마운트 실측치** (높이·각도·화각) — 이게 없어서 차선 좌표 변환 기준값이 아직 가짜다
2. **ESP32 UART 프로토콜** — GPS 속도를 못 받아서 단서 5개 중 `차선 걸침` 1개가 계속 판정 보류 중
3. **카메라 해상도 확정** — 문서엔 640×384, 우리 설정은 320×320으로 안 맞음
4. **링버퍼 클립 요청 형태** (함수 호출 / IPC / 파일) — 이게 정해져야 이벤트에 영상이 붙음
